Measured on this plan page (about 4 characters per token): docs/plan.html is 98 KB, roughly 24k tokens. CSS plus the renderer script are only 14% of it. The option-card data is 59% and the prose body 27%. So markup is not the main cost here. Re-reading a whole page that is mostly content is. The fix is to split by section and read only what changes, and to keep generated pages out of agent context.

Sweet spot: source = TOML + markdown + JSONL, view = generated data-only HTML on a shared viewer, diagrams = node/edge data, Mermaid only for the odd types. Agents write data, the program draws.

Guard rails that save tokens (F38): a context digest verb; deny Read on generated site/; CLAUDE.md and SKILL.md under a size budget with a lint; skills expose name and description only; change files with verbs or small edits, never full rewrites; stable ids plus a generated artifact map so agents find things without reading everything; a terse report shape.

Applied to this plan page (F37): split it into data files (cards, flows, decisions, questions, log) plus a shared viewer and a small build script. Each iteration then reads and edits only the file that changes instead of the 24k-token whole.
